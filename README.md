# Листы Proteus: мониторинг активности и структура HQ

Два листа релиза стоят на одном отчёте TeamPulse и собраны по одной
дизайн-системе (`DESIGN_SYSTEM.md`). Одинаковые по смыслу элементы обязаны
совпадать по вычисленным стилям — см. раздел «Общий словарь двух листов».

## Файлы

| Файл | Что это |
|---|---|
| `activity.sql` | Запрос листа активности. Две гранулярности в одной выдаче: строки `month` (как в 1.0) и строки `week`. |
| `activity.chart.js` | График листа активности: KPI-полоса, состав по категориям, две линии динамики, таблица со спарклайнами, переключатель «Месяцы / Недели». |
| `hq-portrait.data.sql` | Запрос листа структуры: одна строка на сочетание измерений, три счётчика. |
| `hq-portrait.chart.js` | График листа структуры HQ: воронка, пол, возраст, уровень позиции, оформление, стримы, конструктор. |
| `DESIGN_SYSTEM.md` | Дизайн-система TeamPulse. Токены, компоненты, правила визуализации. |
| `Инструкция для Антона.md` | Как забрать релиз из репозитория и поставить оба листа в Proteus, по шагам. |

## Контракт Proteus — менять нельзя

Оба графика написаны под ограничения хоста:

* ECharts — только холст. Вся визуализация — HTML/CSS/SVG в overlay поверх него.
* Хост — **последний** элемент с атрибутом `_echarts_instance_`; его `<canvas>` прячется,
  overlay добавляется через `appendChild`.
* В самом конце файла глобально присваивается пустой `option` со `scatter`.
* ES5: без backticks, стрелочных функций, `let`/`const`.
* Поиск узлов — только `overlay.querySelector`, без `document.getElementById`.
* Семь блоков в фиксированном порядке, без перенумерации:
  `CFG` → вход и хелперы → трансформация → форматирование → разметка → монтаж → `option`.

## Лист активности

### Поток данных

```
витрина ──► activity.sql ──► data[] ──► buildModel() ──► aggregate(подразделение)
             только суммы      строки      индекс по         KPI + ряды графиков
             и счётчики        month       подразделениям    (месяцы и недели)
                               и week      с месяцами        под выбранный срез
                                           и неделями
```

**В SQL нет ни одного деления и ни одной оконной функции.** Запрос отдаёт только
аддитивные величины, поэтому JS пересчитывает весь лист под любое подразделение
на клиенте — клик по строке таблицы не ходит в базу.

Правило отбора колонок: в выдаче остаётся поле, которое нельзя получить
из соседних. Итог по категории не отдаётся — полосы «1–2 недели» и «больше
2 недель» непересекающиеся и покрывают категорию целиком, поэтому итог
складывает JS. Доли, средние, дельты, итог «все подразделения», недельные
доли для спарклайнов — всё в JS.

### Гранулярность: месяцы и недели

Витрина подневная за последние ~4 месяца, поэтому состав по категориям и обе
линии динамики можно смотреть и по неделям. `activity.sql` отдаёт два вида
строк одним набором колонок (`UNION ALL`):

| `row_kind` | Гранулярность | Что несёт |
|---|---|---|
| `month` | подразделение × месяц | состав по `cat_month`, компоненты средних, недельный снимок (`flag_last_week = 1\|2`) и периодовые признаки — ровно как в 1.0 |
| `week` | подразделение × неделя | состав по `cat_week`, численность недели, компоненты средних; снимок и периодовые — нули |

* Переключатель «Месяцы / Недели» стоит в шапке панели состава и действует на
  стек и обе правые панели. Таблица и KPI-полоса — снимок последней закрытой
  недели, они не меняются.
* Неделя — `dateTrunc('week', calendar_dt)`, понедельник. `flag_last_week` в
  строках `week` говорит скрипту, какая неделя последняя закрытая: всё, что
  позже (незакрытая текущая), в ряд не попадает.
* Ось X по неделям: понедельник недели, под первой неделей каждого месяца —
  месяц, под первой точкой — месяц и год. Подписи прореживаются, когда не
  влезают; полные значения — в подсказке.
* Отметка периода (клик по столбцу или точке) живёт в текущей гранулярности
  и сбрасывается при переключении.
* **Совместимость назад:** без колонки `row_kind` или без строк `week`
  (выдача 1.0) лист работает по месяцам, переключатель и спарклайны не
  показываются. Колонки состава переименованы `cnt_month_*` → `cnt_cat_*`
  (в неделях они по `cat_week`); JS читает оба имени.

### Таблица: спарклайны

В блоках «Недоработка» и «Переработка» рядом с «Долей» стоит спарклайн: те же
недельные доли от численности недели за последние 12 закрытых недель
(`CFG.sparkWeeks`), линия в цвете категории, шкала от нуля (§6.1), последняя
точка совпадает с числом рядом. Значения по неделям — в подсказке ячейки.
Недоработку и переработку не складываем: это разные сигналы с разной
логикой реагирования, сумма прятала бы, какая категория растёт. Нет строк
`week` — остаётся одно число, колонки как в 1.0.

### Интерактив

| Действие | Что меняется |
|---|---|
| Клик по строке таблицы | KPI-полоса и оба графика пересчитываются под это подразделение; сверху появляется полоса срезов с чипом. Повторный клик, крестик на чипе или строка «Все подразделения» — сброс. |
| «Месяцы / Недели» | Гранулярность стека и линий динамики. |
| Клик по столбцу состава или по точке линии | Период отмечается: значение в шапке правых панелей переключается на него. |
| Клик по легенде | Категория убирается из стека и из шкалы. Последнюю выключить нельзя. |
| Клик по шапке колонки | Сортировка таблицы, повторный клик меняет направление. |
| `Enter` / `Space` | То же, что клик, для строк, легенды, столбцов и шапок. |
| `Escape` | Снимает срез подразделения и отметку периода. |

### Карта полей

`CFG.fields` задаёт измерения `lvl_down_nm`, `date_structure`, `row_kind`,
`flag_last_week`. Остальные колонки читаются по именам из списков в БЛОКЕ 3:

* `WEEK_KEYS` (11 полей) — снимок последней закрытой недели и предыдущей.
  Берутся из строк `month`, складываются по месяцам внутри подразделения.
* `PERIOD_KEYS` (4 поля) — прогулы и работа в выходные, за весь период.
  По месяцам не аддитивны, поэтому берётся максимум по месяцам подразделения.
* `MONTH_KEYS` (10 полей) — состав по категориям и компоненты средних.
  Чистые суммы; в строках `week` те же поля на неделю.
* `WEEKROW_KEYS` — `cnt_emp` + `MONTH_KEYS`: что читается из строк `week`.
* `SUM_KEYS` — итоги, которых в запросе нет: `low`, `high`, `leave`, `weekend`
  собираются сложением своих полос.

Переименовали колонку в запросе — поправьте соответствующий список.

### Допущения

1. **Сотрудник относится ровно к одному `lvl_down_nm`.** Иначе итог «все подразделения»
   (сумма по строкам) завысится.
2. **Недельный снимок сведён к месяцу** (как в 1.0): если последняя закрытая
   неделя попадает на стык месяцев, её строки лягут в два месяца и сотрудник
   посчитается дважды. Точное решение — третья ветка `snapshot` в запросе
   с `GROUP BY lvl_down_nm`; строки `week` этой проблемы не имеют.
3. **Прогулы и работа в выходные** — периодовые счётчики; максимум по месяцам даёт точное
   значение, когда сотрудник присутствует в витрине во всех своих месяцах.
4. **Неделя витрины = понедельник–воскресенье.** Тогда последняя точка спарклайна
   и число «Доля» в таблице считаются по одному множеству сотрудников. Если
   у `cat_week` другая разметка недели — подставьте её колонку вместо `dateTrunc`.

## Общий словарь двух листов

Одинаковые элементы двух листов совпадают по вычисленным стилям. Это проверено
скриптом в headless Chromium (моки обеих выдач, `getComputedStyle` у пар
элементов), расхождений нет:

| Элемент | Значение |
|---|---|
| Корень листа | фон прозрачный (отдаёт Proteus), Inter 12.5px, без внешних полей |
| Сетка | зазор 14px между панелями, карточками и рядами; порог одной колонки 1120px |
| Полоса срезов | первый элемент листа, только когда срез есть: серая плашка `#f8f9fb` с полями `0 8px`, метка «СРЕЗ:» 10.5 капсом, белые чипы `Измерение: **значение** ×` |
| Панель | белая, радиус 12, тень системы; шапка `14px 16px` с чертой `--line2`, тело `14px 16px` |
| Заголовок панели / подзаголовок | 16px 700 `--ink` / 11.5px 600 `--muted` |
| Переключатель в шапке панели | контейнер `--line2` радиус 12 паддинг 3, вкладка `6px 12px` 12.5px 700 `--muted`, активная белая с тенью, `--ink` |
| Таблица | шапка 10.5px капсом 600 `--muted`, черта `--line2`; ячейка 12.5px 600 `--ink2`, моноширинные цифры; имя и ведущая колонка «Чел.» 700 `--ink`; нули `--muted2`; ховер `#fafbfc`, выбранная `#f5f8ff` с полосой `--act` слева |
| Подсказка | по §5: 12.5px, заголовок 10.5 700, подпись 11.5 600 `--muted`, значение 13.5 700 `--ink` |
| Акцент | `--act #2b6cff`: выбор строки, полосы в ячейках, бейджи, линии динамики. Тепловая карта конструктора — своя шкала (`heatRGB`), это цвет данных, а не акцент |
| Клавиатура | строки, чипы, ячейки конструктора — `tabindex` + `role`, `Enter`/`Space` = клик, `Escape` снимает срезы; `prefers-reduced-motion` |

Что для этого изменилось в `hq-portrait.chart.js` (механика не тронута):
акцент `#2B5EC5` → `--act`; заголовок панели 600 `--ink2` → 700 `--ink`,
подзаголовок 10.5 → 11.5; значения (воронка, карточки, счётчики стримов,
ячейки конструктора) 600 → 700, дочерние строки стримов 500 → 600; ячейки
таблиц 12 → 12.5, имя 700 `--ink`, «Чел.» ведущая, нули приглушены, «%» → «Доля»;
шапка таблицы без серой заливки; ховер/выбор — общие цвета; подсказка по §5
(была 10px с курсивом и капсом, переносы строк не работали); `title=` → `data-tip`;
фокус, `Enter`/`Space`, `Escape` снимает срезы, обработчик Escape не копится
при перезапуске; узкий сегмент стековой полосы остаётся без подписи, чтобы
текст не резался; фон полноэкранного конструктора `--bg` (был прозрачный);
формулировки на «вы».

Что изменилось в `activity.chart.js`: панели получили шапку с чертой и тело
(как у HQ), заголовок панели 13.5 → 16; легенда стека переехала в тело панели,
в шапке — переключатель гранулярности; ячейки таблицы 600; зазоры сетки 14px;
полоса срезов — тот же элемент, что у HQ (класс `hqp-fbar-lbl` из чужого
пространства имён заменён на свой, лишняя `}` в CSS убрана); крестик чипа
наследует кегль.

## Проверка

Оба листа проверены в headless Chromium на моках: выдача с неделями и
выдача 1.0 (только месяцы, старые имена колонок), ошибок консоли нет,
`option` со `scatter` присвоен, переключатель и спарклайны появляются
только при наличии строк `week`, срез/Escape/клавиатура работают на обоих
листах, горизонтального скролла на 1000px нет. Визуальную приёмку на живых
данных Proteus тест не заменяет.
